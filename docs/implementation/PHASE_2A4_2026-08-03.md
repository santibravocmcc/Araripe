## Implemented

- Added a versioned, machine-validated `2 × 2 × 2` candidate registry for two
  drought states, two cloud/shadow masks, and two deterministic daily
  composition methods. The registry is fixed before evidence generation and
  binds the accepted extent, baseline `1.0.0`, the unchanged Phase 2A.3
  package, the processing grid, coverage denominator, source query, and input
  provenance rules.
- Added a local CHIRPS 2.0 monthly-reference builder and validator. It records
  every fixed 1981-01 through 2025-12 reference month and every required 2026
  target month as either a checksummed regional source window or an explicit
  failure. It never substitutes a month, calculates operational drought
  status, or activates threshold adjustment.
- Added provenance-bound candidate evidence generation for the same 60 frozen
  Phase 2A.3 cases. Every complete same-day Earth Search result is retained in
  provider-native item-ID order, with full pagination trace, canonical item metadata,
  required asset metadata, resolved read transport, local window digests,
  accepted-baseline range-read provenance, and raw missing/error states.
- Added deterministic replay validation of both cloud masks, both daily
  compositions, all eight factorial cells, index calculations, accepted
  detector eligibility, confidence results, contributing scenes, selected
  pixels, detector-valid pixels, and fixed-window valid coverage.
- Added a Phase 2A.3-compatible blinded derivative package. Reviewer A and B
  receive isolated packages with deterministic `A`/`B` alternatives and no
  candidate, cell, sample, overlap, or coordinator mapping. The true bijective
  mapping stays under the coordinator directory and is checksum-bound to the
  exact candidate-evidence artifact.
- Extended the offline reviewer flow so primary change assessment must be
  completed before method comparison fields unlock. Review exports remain
  blank initially, qualification and independence attestations remain
  required, and reveal/selection fields are unavailable to reviewers.
- Removed operational SPI switches and calls from all current local detection
  entry points. They now pass `spi_3month=None` explicitly because no qualified
  evidence has selected or activated a drought method.

## Fixed candidate alternatives

### Drought

`drought-disabled-v1` applies no rainfall input or adjustment.

`chirps-v2-spi3-season-matched-1981-2025-v1` uses three complete calendar
months ending immediately before the acquisition month. It compares only
complete windows ending in the same calendar month across the fixed 1981-2025
reference, excludes incomplete reference windows without replacement, and
requires at least 40 complete windows and two positive windows. The mixed-zero
gamma fit, probability clip `[0.001, 0.999]`, SPI threshold `< -1.0`, and
candidate-only z-threshold adjustment magnitude `0.5` are versioned. The
adjustment remains inactive.

### Cloud and shadow mask

`scl-explicit-clear-shadow-v1` uses only the fixed SCL class policy, while
`scl-cloudprob-darkshadow-dilate-v1` additionally uses same-item uint8 cloud
probability, projected dark-NIR candidates, a 1,000 m cloud distance, and 60 m
dilation. Missing SCL, NIR, or cloud probability remains unavailable and never
falls back to the other candidate.

### Deterministic daily composition

`coverage-ranked-first-valid-v1` ranks scenes by integer valid-pixel count and
then provider item ID. `min-cloudprob-sclrank-sceneid-v1` ranks each pixel by
uint8 cloud probability, the fixed non-scientific SCL tie-break, and provider
item ID. Both record every source scene and every scene selected for at least
one output pixel. Selected-pixel and later detector-valid counts are separate,
so a true composite contributor is not erased when its selected pixels later
fail baseline/index eligibility.

No candidate is selected, locked, activated, promoted, or described as more
accurate by this implementation.

## Source normalization and coverage boundary

The accepted baseline uses non-negative Sentinel-2 SR Harmonized reflectance.
Phase 2A.4 therefore fixes
`sentinel2-l2a-stac-scale-offset-zero-fill-nonnegative-v1`: explicit finite
`raster:bands[0].scale` and `offset` metadata are required, raw DN zero is
excluded before bilinear resampling and scaling, scaling is in float32, and
negative scaled reflectance is clipped to zero. Missing or invalid metadata
makes the asset unavailable; `(1, 0)` fallback is forbidden. The exact policy,
effective scale/offset, normalized values, validity, and source metadata are
bound into each local-window digest.

Earth Search currently exposes the required cloud-probability JP2 with a
public `s3://sentinel-s2-l2a/...` provider href. The fixed transport policy
retains that raw provider href and maps only allowlisted public Sentinel
buckets to an unsigned HTTPS URL for range reads of the same bucket/key. A
live small-window smoke check opened all eight required assets and confirmed
the six reflectance normalization records, SCL COG, and cloud JP2.

Coverage always uses every pixel in the fixed case window as denominator. A
valid pixel has finite required reflectance after the selected mask and
composition and is eligible for at least one configured index using finite
current value, accepted baseline mean, and accepted baseline standard
deviation. Per-index standard deviation retains the accepted `0.01` floor.
Coverage below `0.20` remains `rejected_low_coverage`; missing evidence is not
zero.

## Claim and decision boundary

The generated package is comparison evidence, not qualified reviewer evidence.
It contains no scientific method decision and no accuracy, precision, recall,
commission, or omission result. Primary change assessment precedes method
comparison, but no blank review is interpreted as a negative label or a vote.
Technical integrity, deterministic replay, reviewer-tool behavior, and source
availability do not establish scientific accuracy.

No case is replaced, no missing input is hidden, no desired alert total is a
tuning target, and no raw valid detection is deleted or relabeled. Candidate
cell identities and reviewer options are separate from accepted scientific
observation/event identities. Any later method decision requires independently
completed exports from qualified reviewers, agreement/usability assessment,
and an explicit versioned acceptance step outside this package. Replay,
publication, deployment, and release promotion remain separately gated.
