# Phase 2A, Package 2A.1 implementation record

**Date:** 2026-07-28

**Scope:** Persistence, deterministic identity, and scene correctness only

**Production mutation:** None

## Implemented contracts

- The routine Monday/Thursday lookback is five days. Historical ranges remain
  explicit and require an isolated chronological rebuild state.
- Acquisition IDs retain the exact collection, date, provider-native scene
  identifiers, approved monitoring extent, and composition method.
- Observation IDs include acquisition ID, canonical EPSG:4326 geometry,
  algorithm version, and baseline version.
- Origin, split, merge, lineage, and persistence-contribution identities follow
  the accepted Phase 1 formulas. MapBiomas and presentation fields do not
  affect raw observation existence or identity.
- Persistence counts distinct acquisition contributions. An exact retry or
  rolling-window overlap is a byte-stable no-op. An older live acquisition or
  a different acquisition for an already-bound date is rejected.
- One-to-many overlap creates deterministic split children; many-to-one overlap
  creates one deterministic merge child. Superseded parents and lineage remain
  in state. Ambiguous many-to-many components fail closed for reviewed
  correction.
- Scene eligibility is derived from finite current-index, baseline-mean, and
  baseline-standard-deviation pixels. Cloud, NoData, and invalid pixels are
  excluded from both the anomaly numerator and denominator.
- Accepted and rejected scene QA records include coverage, valid/total/alert
  pixel counts, thresholds, flags, and an explicit rejection reason. Raw
  accepted observations carry the relevant QA fields.
- Headless and manual GEE inputs must supply deterministic scene provenance.
  Missing or inconsistent metadata is an error; identities are not guessed.

The working persistence GeoJSON now has deterministic top-level metadata and
nested event/contribution/lineage records. Legacy state is deliberately not
silently upgraded because its duplicate contributions cannot be recovered
reliably. The corrected 2026 generation must be rebuilt chronologically later;
the current audit generation remains untouched.
