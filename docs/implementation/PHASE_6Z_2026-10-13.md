## 2. O aviso na página — `site#47`

Decisão do dono de 2026-10-10 (PHASE_6Y §9): a página diz "dados atrasados" só
quando a última data **olhada** passa de 21 dias.

**O briefing nomeava o campo errado.** Ele dizia
`coverage.last_observed_on` *do índice verde*; o índice não tem `coverage`
(propriedades de `docs/contracts/phase2b/schemas/site-alert-index-v1.schema.json`:
`schema, stats_policy_version, runs, unanalyzed_dates, strong_points_file,
totals, last_run, source, object_base, land_cover`). O **ponteiro** tem: o campo
é obrigatório em `green-pointer-v1` e `-v2`, e `atomic_publish.py:556` o copia do
documento da release. A página já lê o ponteiro e já recusa um índice de outra
release, então a data é a da release mostrada. É o mesmo campo e a mesma conta
que `green_status.py` julga como `alerts.observed`.

Feito: `carregaFonteVerde` devolve `ultimaOlhada`; `dadosAtrasados(data, agora)`
conta dias inteiros por data UTC, atrasado se `> 21`; `montaTresDatas` põe a
linha antes das três datas. Um ponteiro sem a data não recusa o verde (o aviso
é acréscimo), só não avisa. Um teste lê os dois limites do backend (21 e 5) e
os prende aos da página.

`npm run test:worker` 223 (216 + 7); `pytest` do site 227; `vite build` ok.
Mutações, cada uma sozinha: `>` → `>=` (1 falha), a data de `runs[]` no lugar
