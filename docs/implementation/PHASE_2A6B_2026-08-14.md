## `scl-explicit-allowlist-v2` (src/processing/scl_mask_v2.py)

The mask is an explicit allowlist bound test-by-test to
`config/phase2a_candidate_generation_decisions_v2.json`:

- SCL 4/5/6/7 accepted; SCL 0/1/2/3/8/9/10/11 rejected; the partition is
  tested to be complete and disjoint over the twelve known classes.
- Missing SCL, non-integer SCL, non-2-D or empty grids, and any value outside
  0–11 fail closed with typed exceptions whose stable lowercase reason codes
  (`scl-missing`, `scl-unexpected-value`, `processing-baseline-missing`,
  `processing-baseline-unexpected`, `processing-baseline-unreviewed`) are
  valid processing-ledger-v2 reason tokens.
- The processing baseline is read with the fixed priority
  `s2:processing_baseline` then `PROCESSING_BASELINE`. A present-but-null or
  present-but-invalid higher-priority field fails closed instead of falling
  through. Only the provider's decimal string is accepted and it is
  normalized without rounding: the major component is zero-padded and every
  fractional digit is preserved verbatim (`"5.11"` → `"05.11"`, `"05.10"`
  stays `"05.10"`); numeric types, whitespace, and any other shape fail
  closed.
- Provider datatake identifiers (`GS2X_..._NNN.NN`) are cross-checked against
  the read baseline; a disagreeing suffix or a malformed `GS2*` identifier
  fails closed. All 70 retained Phase 2A.4 pilot scenes satisfy this
  consistency.
- Class 2 is rejected under both semantics across PB04: the QA records
  `dark-area-pixels` below baseline `04.00` and `cast-shadows` at or above
  it, with `scl_class2_accepted: false` in both regimes.
- There is no dark-NIR proximity mask and no shadow dilation; the QA records
  both tokens literally.
- The SCL 7 fraction of accepted pixels is recorded per scene (null when
  nothing is accepted) alongside full per-class pixel counts. The QA embeds
  `provisionally_clear`, `scientifically_validated: false`, and
  `public_quality_claim_permitted: false`; no validation claim is made.

The reviewed-baseline registry
`araripe-reviewed-processing-baselines-v1 = {05.11, 05.12}` is the complete
enumeration observed across the 70 retained Phase 2A.4 pilot source scenes
bound by the 2026-08-11 decision. Any other value — including well-formed
ones such as `05.10` or `99.99` — fails closed as unreviewed until a recorded
review extends the registry; extension is an explicit argument, never a
fallback.

## `coverage-ranked-first-valid-v1` (src/processing/composition_v2.py)

Composition is scoped to exactly one physical datatake
(`datatake-scoped-v2`):

- Scenes are strictly partitioned by normalized platform plus datatake
  identifier; groups are never merged, duplicate scene IDs fail closed, and a
  scene whose platform disagrees with its `GS2X_` datatake prefix fails
  closed. Two same-day datatakes therefore always yield two independent
  composites, byte-identical to composing each alone.
- Scene validity is the SCL allowlist AND the intersection of finite values
  across every band, so a pixel with any missing band falls through entirely
  to the next scene; per-scene `accepted_but_nonfinite_band_pixel_count` is
  recorded.
- The explicit order is `valid_pixel_count` descending, then provider-native
  scene ID UTF-8-byte ascending; ties and multibyte identifiers are tested.
- Each pixel takes all bands from the first valid scene in that order. The
  contributor map (int32, sentinel −1, indexed into the recorded composition
  order), chosen-SCL grid, and per-scene contributor counts reconcile with
  composed/uncomposed/total pixel counts.
- Mask evaluation iterates scenes in UTF-8 scene-id order so a multi-failure
  datatake surfaces the same fail-closed error for every input permutation;
  an order-dependent reason would poison terminal-row retries.
- Band sets, grid shapes, and band dtypes must be uniform across the scenes
  of a datatake; integer bands fail closed because nodata is representable
  only as NaN.
- The composite records the SCL 7 share of composed pixels (null when the
  composite is empty) under the same no-validation-claim QA flags, plus the
  enumeration of every observed processing baseline and the reviewed
  registry.
- A fully deterministic evidence document (method tokens, order policy,
  per-scene QA, contributor accounting, array SHA-256 digests) is produced
  with a canonical `composition_evidence_sha256`. Input-permutation
  invariance and repeat-run byte identity are proven against an independent
  per-pixel brute-force reference implemented in the tests.

A zero-valid composite is representable (all bands NaN, contributor map all
sentinel) rather than an error, so coverage-based rejection stays an explicit
ledger decision.

## Explicit GEE-equivalent path (src/processing/gee_composition_v2.py)

Earth Engine `mosaic()` keeps the last valid image, so implicit order is the
documented seam risk. The module makes the order explicit and provable
without any live GEE connection:

- `build_gee_composition_plan` derives a self-checksummed
  `gee-coverage-ranked-first-valid-plan-v1` from a local composite: the
  scientific `first_valid_order`, its exact reverse as `mosaic_input_order`
  (worst first, most-preferred last), the single-shared-mask rule
  (`updateMask` every band with one combined SCL-allowlist ∧ all-band mask so
  `mosaic()` cannot mix bands of one pixel across scenes), per-image constant
  contributor-rank bands, and the expected per-scene valid-pixel counts.
- `execute_gee_plan_locally` emulates the plan with genuine mosaic paint-over
  semantics (later valid image overwrites earlier), a deliberately different
  algorithm from the first-take reference. It recomputes masks and counts
  from the raw scenes and fails closed on plan-checksum tampering,
  non-reversed order, scene-set mismatch, or any count drift — the same gates
  a future live GEE run must pass before its mosaic may be compared.
- `assert_local_gee_parity` requires byte-identical composed bands,
  contributor map, chosen SCL, contributor counts, and SCL 7 accounting, and
  returns checksummed parity evidence. Tests prove parity for the reference
  fixture, every input permutation, coverage ties, and zero-valid
  composites — and prove that a wrongly ordered but well-formed plan executes
  to a different composite that the parity gate refuses.

The live execution of this plan on Earth Engine belongs to a later package
with the approved Earth Engine project; nothing here contacts GEE.

## Manifest-bound run producer (src/detection/composition_run_v2.py)

`CompositionRunV2` consumes — never redefines — the closed 2A.6A family:

- Each declared physical datatake (platform, datatake ID, acquisition
  timestamp, native scenes) becomes exactly one `AcquisitionV2` bound to
  `coverage-ranked-first-valid-v1` and the caller's grid. Declared
  timestamps must equal the sensing instant embedded in provider datatake
  identifiers; foreign scenes, duplicate physical keys, and scene sets that
  do not form exactly the declared datatake fail closed.
- The expected set seeds a `ProcessingLedgerV2`. `compose_all` composes every
  acquisition, proves local/GEE-plan parity for each success, and records
  fail-closed terminal rows for mask-unavailable datatakes: missing
  SCL/baseline metadata → `failed_missing_input`; unexpected or unreviewed
  metadata → `rejected_quality`, with the typed reason codes above.
- Detection outcomes remain the caller's: `record_complete` accepts only
  `ObservationV2` records of that exact acquisition and algorithm version and
  writes `complete_with_alerts`/`complete_zero_alerts` with the composition
  evidence checksum as the artifact; `record_zero_valid` writes
  `rejected_low_coverage` (`composite-zero-valid-pixels`) only for an empty
  composite. The 30% coverage threshold decision is intentionally not
  consumed here; it remains with the detection stage.
- `run_evidence` serializes only over a fully terminal, daily-reconciled
  ledger and enumerates every observed processing baseline — including
  values surfaced by unreviewed failures — plus the registry, per-acquisition
  statuses, evidence checksums, GEE plan checksums, and parity flags, under a
  canonical `run_evidence_sha256`. Ledger serialization, daily summaries, and
  `date_input_digest` stability across identically rebuilt runs are covered
  by the focused tests.

## Discovered contract gap: Sentinel-2C

20 of the 70 retained Phase 2A.4 pilot scenes are Sentinel-2C
(`platform: sentinel-2c`, datatakes `GS2C_*`), but the closed acquisition-v2
schema and runtime restrict `platform` to `S2A`/`S2B`. This package stays
platform-neutral (labels A–D normalize mechanically) and the closed contract
fails closed on S2C, which is tested and correct fail-closed behavior — but it
means a 2026 replay would currently reject every Sentinel-2C datatake as
unrepresentable rather than process it.

This is a pre-existing 2A.6A contract boundary, not a 2A.6B regression. It is
deliberately not patched here: widening the platform enum changes the closed
contract family and requires an explicit owner decision (an additive reviewed
amendment to the acquisition-v2 schema, runtime, examples, and validator)
before Package 2A.6C/2A.6D replay work. Until then the gap is visible,
fail-closed, and documented.

## Independent adversarial review

A pre-review self-audit found and fixed one determinism gap before the
independent pass: mask evaluation originally iterated scenes in input order,
so a multi-failure datatake could surface different fail-closed reasons for
different input permutations, poisoning byte-identical terminal-row retries.
Scene gates now run in UTF-8 scene-id order under a permutation regression.

An independent read-only adversarial review of the four new modules and
their tests then ran thirteen concrete counterexample probes against policy
fidelity, determinism, parity soundness, contract consumption, fail-closed
completeness, and scope. It reported **no blockers**, independently
reconfirmed the reviewed-baseline registry against the 70 pilot scenes
(exactly `05.11`×8 and `05.12`×62, all datatake suffixes agreeing), and
found three MAJOR hardening gaps with working counterexamples plus four
MINOR items and five notes. All three MAJORs and the four MINORs are fixed
in this package, each with a new regression:

- MAJOR (fixed): `numpy.ma.MaskedArray` SCL or band inputs were silently
  de-masked by `np.asarray`, so nodata fill values could pass the allowlist
  or contribute to a composite — a realistic `rasterio(masked=True)`
  integration path around the fail-closed policy. Masked arrays are now
  rejected typed at both the mask evaluator and scene-input boundaries.
- MAJOR (fixed): one physical datatake could occupy two expected
  acquisitions in one manifest via a microsecond-different declared
  timestamp, because the 2A.6A ledger physical key compares exact timestamp
  strings while the GS2 embedded-instant check truncates to seconds. The run
  producer now requires platform/datatake uniqueness across the declared
  manifest.
- MAJOR (fixed): the mutable outcome record allowed swapping a foreign
  composite onto another acquisition, recording a genuinely zero-valid
  acquisition as complete with a foreign artifact checksum. Terminal-row
  recording now verifies run membership and that the composite's platform,
  datatake, and scene set equal the outcome's acquisition.
- MINOR (fixed): the GEE-plan executor did not validate declarative plan
  fields, so an inert tamper (wrong mask block, or reordered tied/zero
  scenes) could survive with a recomputed checksum; it now rejects any plan
  whose method/mask block differs from the fixed policy or whose
  `first_valid_order` is not the coverage-ranked order derived from the
  recomputed counts.
- MINOR (fixed): band-set/dtype uniformity errors were input-order
  dependent; structural gates now use the UTF-8-least scene as reference.
- MINOR (fixed): a multi-scene failed datatake enumerated only the first
  failure's baseline; a metadata pre-pass now reads every scene's baseline
  before raising and attaches the complete observed enumeration to the typed
  error, which run evidence consumes.
- MINOR (fixed): `SceneInputV2` aliased caller arrays, so later caller
  mutation changed composites; inputs are now validated read-only copies
  with an aliasing regression.
- NOTES: executor shape drift now raises a typed parity error; the composite
  SCL 7 QA block carries the full no-validation-claim policy including
  `phase5_validation_required`; the class-2 QA label now follows the scene's
  PB04 regime. Two notes were accepted without change: terminal-row
  recording raises on an already-terminal outcome rather than delegating to
  the ledger's byte-identical no-op (stricter than the contract, not
  unsafe), and a manifest containing any Sentinel-2C datatake fails whole-run
  at construction — see the contract-gap section, which the review flagged
  as replay-blocking granularity worth the owner's attention.
